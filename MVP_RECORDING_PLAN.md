# RustDAW Recording MVP

## Goal

Build a small, dependable Ubuntu recording application for this workflow:

1. Connect a guitar/pedal to the Focusrite Scarlett Solo 4th Gen, or select the pedal's USB audio input.
2. Create a mono or stereo audio track.
3. Choose the track's physical input.
4. Enable monitoring and arm the track.
5. Set tempo and enable the click.
6. Record, stop, play back, and save the session.

This MVP does not include plug-ins, MIDI editing, automation, comping, buses, or advanced editing.

## Confirmed development-machine audio setup

- PipeWire and WirePlumber are running.
- Scarlett Solo 4th Gen is visible through ALSA/PipeWire.
- Scarlett stereo playback is the active output.
- Scarlett capture is currently exposed as four channels by the PipeWire profile.
- A MOOER GE200 USB audio source is present in saved PipeWire configuration and can be supported as an alternative input when connected.

Do not assume that PipeWire channel names map directly to the Scarlett's front-panel labels. Add a short input-identification test and store the verified mapping in application preferences.

## Version 0.1 user interface

One window with four areas:

- Toolbar: play, stop, record, return-to-start, time display, tempo, time signature, click on/off.
- Track list: add mono, add stereo, name, input selector, arm, monitor, mute, gain, and level meter.
- Timeline: playhead and recorded regions; zoom and horizontal scroll.
- Status bar: audio device, sample rate, buffer size, XRUN count, and recording path/free space.

Essential shortcuts:

- Space: play/stop
- R: toggle record-arm on selected track
- Ctrl+Space: start/stop recording
- Home: return to start
- C: toggle click
- Ctrl+S: save

## Audio routing model

Each track has a channel layout and an explicit input route:

```text
Mono track   <- one hardware capture channel
Stereo track <- ordered pair of hardware capture channels

Track playback --+
Live monitoring --+--> master stereo mix --> Scarlett outputs 1–2
Click ------------+
```

For guitar or a mono pedal output, create a mono track and select the Scarlett instrument input's verified channel. Do not record a mono source to a stereo track: it wastes space and commonly places the signal on only one side.

The application should display stable friendly names such as `Scarlett Input 1` while retaining the backend node and port identifiers used to reconnect. If a device disappears, keep the route unresolved instead of silently selecting another microphone.

## Recording behavior

- Default project format: 48 kHz, 32-bit float internal processing.
- Recorded files: mono or stereo 24-bit WAV/BWF at the device sample rate.
- One file writer per armed track, fed through a bounded preallocated ring buffer.
- Audio callback interleaves/deinterleaves only into prepared buffers; disk writes happen on worker threads.
- Start all armed tracks on the same engine sample for alignment.
- Create a temporary recording file before transport starts.
- Update recovery metadata while recording and finalize the WAV/BWF header on stop.
- If the disk writer cannot keep up, show a recording error and preserve every recoverable sample.
- Preflight writable path and free disk space before record begins.

## Click track

The click is generated by the engine, not scheduled by the UI.

- Tempo range: 20–300 BPM.
- Initial meters: 4/4, 3/4, and 6/8.
- Accent beat one with a distinct sound.
- Schedule click positions using integer/rational musical time, then convert them to exact sample positions.
- Mix click into the monitor/master output but never into recorded input files.
- Provide click level and optional one-bar count-in.
- The click remains sample-aligned across different callback sizes.

Use short built-in synthesized clicks initially to avoid asset and licensing complexity.

## Monitoring

Support two clearly named modes:

- Hardware/direct monitoring: the Scarlett handles the live guitar signal; RustDAW plays existing tracks and click. Lowest latency, but the application cannot control the direct signal level.
- Software monitoring: RustDAW routes captured input back to the Scarlett output. Useful for future effects, but depends on buffer size and system stability.

Prevent accidental double monitoring by warning users when software monitoring is enabled while direct monitoring is likely active. Start testing at 48 kHz with a 256-frame buffer, then validate 128 frames after the engine is stable.

## Minimal project model

```text
Project
  sample_rate
  tempo
  meter
  tracks[]
  regions[]

Track
  id, name
  layout: Mono | Stereo
  input_route
  armed, monitoring, muted
  gain

Region
  track_id
  timeline_start_sample
  source_file
  source_start_frame
  frame_count
```

Save a versioned project manifest atomically. Store recordings in a project-local `Audio/` directory and disposable waveform caches in `Cache/`.

## Implementation sequence

### Sprint 1 — hardware proof

- Create Cargo workspace and headless engine test harness.
- Enumerate PipeWire/JACK capture/playback ports with stable IDs and friendly names.
- Build Scarlett duplex pass-through with peak meters.
- Log sample rate, quantum, callback duration, and XRUNs outside the callback.
- Run an input-channel identification utility for the Scarlett and GE200.

Done when a selected physical input is heard through outputs 1–2 for 30 minutes without an application XRUN at the baseline settings.

### Sprint 2 — safe mono recording

- Add transport/sample clock and one mono track.
- Implement ring-buffered disk recording and temporary-file recovery.
- Record the selected Scarlett or GE200 channel to mono WAV.
- Play the recording back through the Scarlett.
- Test stop, application crash, device removal, disk full, and power-interruption simulation.

Done when ten consecutive interrupted and normal recordings preserve the expected recoverable audio and start at the correct sample.

### Sprint 3 — tracks and click

- Add multiple mono/stereo tracks and input routing.
- Add sample-accurate metronome, tempo, meter, level, and count-in.
- Align simultaneous recordings from multiple armed tracks.
- Add playback mixing, mute, track gain, and master limiter-free metering.

Done when a guitar take can be recorded against a click and earlier tracks, with click absent from the recorded source files.

### Sprint 4 — usable desktop

- Add the recording-focused UI, shortcuts, waveform generation, and timeline display.
- Add project creation, save/open, atomic manifest replacement, and recent sessions.
- Add clear direct/software-monitoring controls and device diagnostics.
- Package a development build for the target Ubuntu machine.

Done when the complete target workflow can be performed without a terminal and the saved project reopens identically.

## Acceptance test for version 0.1

1. Launch with the Scarlett connected and select it as input/output.
2. Create a 48 kHz project at 120 BPM.
3. Create one mono guitar track and select the correct instrument/pedal input.
4. Enable click and a one-bar count-in.
5. Record continuously for 30 minutes while monitoring and playing existing tracks.
6. Add a second mono take and one stereo track.
7. Save, close, reopen, and confirm alignment and routing.
8. Export a stereo WAV and compare its duration and peak levels to live playback.
9. Force-close during a second recording and confirm recovery on restart.

The release passes only with no corrupted project, no click leakage into source recordings, no unexplained channel swapping, and no application-caused XRUN on the reference configuration.
